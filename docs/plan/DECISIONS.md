## 2026-10-09: Art pipeline (Phase 8)

- One prompt source (`docs/art/prompts/*.md`) for both generation routes: by hand (`generate.mjs --dry-run`, free) or the OpenAI Images API (`IMAGE_API_KEY`, a few cents an image, run only when James asks). Default is by hand until James adds a key.
- Background removal is a flood fill from the image edges through paper-coloured pixels (`scripts/art/remove-bg.mjs`), not an ML model: our art is always drawn on plain paper with thick outlines, and this needs no 100 MB model download. If it struggles on real images, fall back to `@imgly/background-removal-node`.
- Text on covers and OG cards is drawn by script in the brand fonts, never by the image model.

## 2026-10-09: Analytics (T7.9)

Cloudflare Web Analytics, not GA4. It is free and cookieless and collects no personal data, which is right for a kids' site and the App Store Kids category, and needs no consent banner. The beacon goes in production builds only, through `brand.analyticsId` (the site token) and the brand-html Vite plugin, never inline. Cloudflare has no custom events, so game plays are counted first-party in the `plays` table (admin dashboard); `utils/analytics.ts` keeps the SDK's event calls as dev-only logs. GA4 (`G-8EJGYV0500`) is no longer loaded.

## 2026-10-09: Sign-in throttling and account deletion (T7.7, T7.8)

- PIN sign-in is throttled in Postgres (`auth_attempts`): 5 failures per username and 20 per hashed IP in 15 minutes, and 5 wrong current PINs per account on change-pin; then 429 with Retry-After. IPs are stored only as SHA-256 hashes, and attempts older than a day are deleted daily. Unknown usernames get the same message and a dummy bcrypt check, so neither the message nor the timing gives away whether a username exists.
- Express `trust proxy` stays off: on Lambda, serverless-http takes `req.ip` from API Gateway's `sourceIp`, which the client can't forge. Revisit if CloudFront ever sits in front of the API.
- `DELETE /me` removes the user and the Firebase account. Plays are kept anonymised (`user_id` null), but best scores, stats, friends, stickers and ratings go with the account, so a deleted player disappears from leaderboards. This supersedes the plan's "Deleted player" wording, because removing them is the more private choice.

## 2026-10-09: Contrast and overlays (T7.11, T7.12)

## 2026-10-09: Share cards (T11.5)

- The card image is made by the API Lambda on request, not by a separate Lambda, and is not stored in S3: CloudFront caches it for a day (`Cache-Control: public, max-age=86400`), which is all the caching a family site needs.
- Rendering: the card is SVG with every word turned into paths by opentype.js from the brand WOFF fonts (Baloo 2 and Nunito, as in the brand scripts), rasterised by **`@resvg/resvg-wasm` 2.6.2** (pinned exactly; published March 2024). It is WebAssembly, so it bundles with esbuild and needs no Linux-specific native binary (unlike `sharp`), and satori would have added a second layout engine for one fixed layout. Cost: the Lambda zip grows from 0.9 MB to about 2.1 MB (resvg's .wasm ~0.95 MB zipped, opentype.js ~0.25 MB minified), under the 3 MB target. `scripts/bundle.mjs` copies the .wasm and the two fonts next to `lambda.mjs`. opentype.js and the fonts come from the root dev dependencies the brand scripts already use.
- Share links are `https://games4james.com/s/<playId>`. A CloudFront behaviour for `/s/*` points at the API (MANUAL step in `infra/cloudfront/README.md`), so bots and people both get the API's preview page; its script sends people on to `/games/<gameId>`. The bot rewrite stays as it is. Until the behaviour exists the app's own `/s/:playId` route opens the game, so links never break.
- The card shows the screen name only (never the username). Deleted or disabled players are "A player", plays on inactive games have no card (404), remix plays name the remix, and names the Latin brand fonts can't draw fall back to "a player" on the image (the page title still has the real name). Share pages are `noindex`.

## 2026-10-09: Remix mode (T11.2)

- **Remix runs have their own board only.** A run on a saved remix (`POST /scores` with `remixId`) earns XP, counts for the streak, daily stats and stickers like any run, but it never raises the game's best score or the game's leaderboard (`best_scores`), and the admin "delete play" rebuild ignores remix plays too. Otherwise a slow-croc, five-lives remix would top the normal board. `newBest` on a remix run means "your best on this remix". On the device, a remix keeps its own best (`g4j:best:<gameId>~remix-<id>`).
- **Unsaved slider runs aren't posted.** The server can't tell them from a normal run, so trying sliders is practice; saving the remix gives it a board ("Save your remix to give it a scoreboard").
- **Knob ranges: the API bundles `apps/player-web/public/game-meta.json`** (`src/data/remixKnobs.ts`, a JSON import that esbuild inlines into `lambda.mjs`), rather than seeding them into the database: `games.metadata` belongs to the admin and a new column would need a schema change. A manifest knob change therefore reaches the server with the next API deploy (which already re-exports and bundles). Values must be inside [min, max] on the step grid, unknown keys are refused, missing ones get the default, and a remix that changes nothing is refused.
- **Remix names** use the screen-name obscenity matcher with looser rules: 3 to 24 characters, letters, digits, spaces, `-`, `'`, `!`, `?`; no `@`, dots or slashes and no runs of 5+ digits (no emails, links or phone numbers). The makers' names are allowed ("Tilly's super-fast crocs"). Saving needs a registered account; each player may keep 50 remixes. `GET /remixes/:id` is public (name, game, knobs, the maker's screen name and avatar; never the maker's id).
- Knobs shipped: Snapadile croc speed (also spawn rate), lives and croc size; Hoop City gravity and space between hoops (the ring opening is fixed by the ring art, so "ring gap" is the gap between rings); Blocker pieces to pick from (1 to 4). Every default is today's game.
