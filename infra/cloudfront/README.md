# CloudFront Functions

## `bot-rewrite.js`: per-game link previews

**What it does.** The site is a single-page app, so every URL returns the same `index.html` with the home page's title and image. Link-preview bots (WhatsApp, iMessage, Slack, Discord, Facebook, X) don't run JavaScript, so without this every shared game link looks the same. This viewer-request function sends bots asking for `/games/:id` to `/static-games/:id.html`, a small page with that game's title, description and `og:image`. People get the app as normal.

The static pages are generated by `scripts/generate-sitemap.mjs` on every build (`npm run web:build`).

Tests: `node --test "infra/**/*.test.mjs"` (included in the root `npm test`).

### MANUAL (James): attach it once

Console route (about five minutes):

1. AWS console → CloudFront → **Functions** → **Create function**. Name `g4j-bot-rewrite`, runtime **cloudfront-js-2.0**.
2. Paste the contents of `infra/cloudfront/bot-rewrite.js` into the editor → **Save changes**.
3. **Test** tab: event type *Viewer request*, URL path `/games/snapadile`, add header `user-agent: Twitterbot/1.0` → **Test function**. The output URI should be `/static-games/snapadile.html`.
4. **Publish** tab → **Publish function**.
5. Same page → **Add association**: distribution = the games4james.com distribution (its id is the `WEB_CLOUDFRONT_DISTRIBUTION_ID` repo variable), event type **Viewer request**, cache behaviour **Default (\*)** → **Add association**. Wait for the distribution to show *Deployed*.

Or with the AWS CLI (Claude can run these if you approve `aws` commands):

```bash
aws cloudfront create-function --name g4j-bot-rewrite \
  --function-config '{"Comment":"Bots get static game pages","Runtime":"cloudfront-js-2.0"}' \
  --function-code fileb://infra/cloudfront/bot-rewrite.js
aws cloudfront publish-function --name g4j-bot-rewrite --if-match <ETag from the previous output>
# then add the association to the distribution's DefaultCacheBehavior.FunctionAssociations
# (get-distribution-config → edit → update-distribution).
```

**Cache key.** The function changes the URI before the cache lookup, so bot and human responses are cached under different keys. No cache-policy change is needed.

### Check it works (after the next deploy)

```bash
curl -s -A facebookexternalhit https://games4james.com/games/snapadile | grep -o '<meta property="og:image"[^>]*>'
curl -s https://games4james.com/games/snapadile | grep -c static-games
```

The first should print the Snapadile image. The second should print `0`, meaning people still get the app.
